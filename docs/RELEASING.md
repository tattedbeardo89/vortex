# Releasing Vortex

1. Merge a reviewed functional change. Bump only custom/vortex/brand.json version (stable major.minor.patch; limits 99.999.999). Never copy an upstream release version over it. PS5 content version is derived automatically. Do not change the installed title/content IDs for a normal update.
2. Run Vortex/app regression tests and the complete PS5 build. Review inherited framework failures separately. Confirm the generated Vortex name, title/content IDs, independent feed, packaged notices and Vortex.exfat/update.zip naming.
3. Manually dispatch Build Vortex in tattedbeardo89/vortex. It uploads the exFAT image, update ZIP, identity manifest, validation report, provenance receipt and repository source snapshot. Draft creation defaults off; artifact-only builds do not create a release. Opting in creates a draft only. No synchronization event publishes anything.
4. Test the exact artifacts on an authorized supported console, including coexistence with Overdrive, state persistence, browsing, controller input and self-update/recovery. Record firmware, loader and artifact hashes. This implementation does not claim those tests.
5. Before any binary publication, review rights to recovered app source, catalog/game artwork and all dependencies. Preserve MyLuxy, PS5 React/half144 and third-party notices. The Vortex-source.tar repository snapshot alone is NOT all GPL corresponding source: collect the exact downloaded GPL dependency sources and patches, build recipes/toolchain information and any additional required source/notice material using the receipt, dependencies.lock.json and ps5-react/docs/DEPENDENCIES.md. Keep UnRAR separate, preserve its license, and respect its restrictions. Do not publish until the redistribution requirements are satisfied.
6. Explicitly publish the tested draft through GitHub after approval. Never create a public release as part of sync. GitHub must expose a SHA-256 digest for update.zip; without it clients refuse the update. The Vortex release asset URL must be exactly https://github.com/tattedbeardo89/vortex/releases/download/v<version>/update.zip.

The draft tool refuses to modify an already published version. Retest a draft after any asset replacement. For rollback, publish a NEW, higher Vortex version built from the previous working source; clients intentionally refuse automatic downgrades. Alternatively install a trusted previous Vortex.exfat manually while the application is closed, preserving the title ID and keeping backup copies outside the watched homebrew directory.
