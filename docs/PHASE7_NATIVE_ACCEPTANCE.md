# Phase 7: native navigation, Settings viewport and registered artwork

Baseline: main `cf9a1de`, plus unmerged PR #6 head `73642f9`. This change is stacked on PR #6. Selected commercial source remains Overdrive v1.0.8 (`9f90d882`); no catalog, provider, download or authentication policy changes. Version 1.2.2 distinguishes this image from physically tested 1.2.1.

## Confirmed causes and changes

* The protected sidebar adapter replaced Header's rendering, but retained `useSections.step`: the upstream array includes Search, Top rated and Files, excludes PS4/PS5 and Settings, and does not wrap. This explains Downloads + R1 → Files. The eight primary entries in `custom/vortex/native/navigation.js` now own order, labels, highlight, routing and content focus targets. L1/R1 uses that registry, with fixed forward/reverse vertical order in every language. Visible Search, Top rated, Files, Genres and Language tools remain available outside the cycle. A native regression also found that Header closed the genre menu before checking modal ownership on R1. The modal guard now runs first, preserving the originating focus on dismissal. Original keyboard input ownership, queue shortcuts and the working card Left override are retained. Explicit Left exits cover the hero CTA, catalog filter, first Homebrew chip and empty Downloads control; loading/empty Homebrew has a visible Back to sidebar control, so it never strands focus without content. Scope memory restores mounted content; remounted destinations use a valid registry target, avoiding stale card keys.
* WebPanel was a fullscreen overlay whose ScrollView had padding but no bounded flex viewport. The content could grow beyond the screen, so the focus manager could not reveal controls reliably. It also put many diagnostic lines before pairing. Settings now occupies a bounded content viewport (left 320, right/top/bottom 32), uses the original framework's focus-revealing ScrollView with flex:1, clipping, nonshrinking contents and bottom padding. The sidebar remains stationary. The first and last controls clamp directional focus; Left returns to the active sidebar entry and Right returns to Settings scope memory. Underlying content is inert while Settings is open. Web status, toggle, pairing code and devices precede connection options and diagnostics. A visible shortcut inside Settings opens the original language/download-limit/controller settings sheet; dismissal restores and reveals its originating control. A newly generated code receives focus and its bounds are measured.
* The earlier image contained Angular V icon0.png and BC7 pic0/pic1, and the framework hides the system splash after presenting its first frame. The protected React splash already uses the Angular V master. There is no confirmed Overdrive-native early splash component to replace.
* ShadowMount source `0794096dbfd5855d5b757e4708703671400bc9cf`, `src/sm_install.c`, demonstrates **three retained artwork locations**: `/user/appmeta/PPSA99189`, `/user/app/PPSA99189/sce_sys`, and `/user/app/PPSA99189/icon0.png`. It skips appmeta copying on remount when existing metadata is found, and skips staging under another condition. The PR #6 refresh covered appmeta only. This change includes verified title staging and root icon copies where present. This is a confirmed incomplete-refresh mechanism, **not proof of which cache/files the user's console currently displays**. No console filesystem, loader version or mount was inspected remotely.

## Read-only diagnosis BEFORE any registration write

1. Close/unmount any old Vortex image before replacing it. Keep one intended Vortex image; preserve downloads and `/data/vortex/PPSA99189`. Do not delete settings, favorites, paired devices or Overdrive's separate installation.
2. After mounting the new image, open Settings & Devices. Compare compiled commit/version with the downloaded build, and require mounted assets to match. Do not diagnose by version number alone.
3. Navigate down to **Inspect mounted and registered artwork (read-only)**. It reports compiled and mounted artwork revision; expected hashes compiled into the application; actual mounted, appmeta, staged sce_sys and root-icon hashes. Unreadable/missing files are unknown, never reported as matches. This operation cannot read arbitrary paths or device records. It does not prove the PS5 shell's in-memory cache contents.
4. Optionally export only static files with your existing read-only console tooling: `/app0/VORTEX-BUILD.json`, `/app0/VORTEX-BRANDING.json`, `/app0/sce_sys/{param.json,icon0.png,pic0.dds,pic1.dds}` into `mounted/`; `/user/appmeta/PPSA99189/{param.json,icon0.png,pic0.dds,pic1.dds}` into `registered/`; and `/user/app/PPSA99189/{icon0.png,sce_sys/param.json,sce_sys/icon0.png,sce_sys/pic0.dds,sce_sys/pic1.dds}` into `staged/`. Do not export pairing records or cookies. The file-transfer command depends on the tooling already installed on your console; this task does not install or expose a console file service.
5. Run against the trusted downloaded artifact's metadata directory:

   ```sh
   python3 custom/vortex/inspect_installation.py --reference artifact/metadata --mounted mounted --registered registered --staged staged
   ```

A wrong compiled/mounted commit indicates an old or mixed installation. A correct mounted checksum with a different registered/staged checksum identifies stale disk artwork. Matching all disk checksums with a wrong home icon points to a shell cache or another loader/registration location that still needs console evidence. Do not modify databases or delete caches based on that hypothesis.

## Explicit safe artwork refresh and rollback

Only after inspecting the above, choose **Refresh registered PS5 artwork**, then the separate **Confirm Vortex-only artwork refresh and backup** action. This is console-only; no browser endpoint can request it. It validates both mounted and target title/content IDs and every mounted artwork hash against compiled expectations. It backs up all affected artwork and param.json metadata before replacing any artwork. First-original backups remain under `/data/vortex/PPSA99189/artwork-backup`, including `staged/` and `staged-root-icon0.png`. Only existing, verified Vortex artwork targets are replaced, using the framework's synced temporary copy + rename. The operation is atomic per file, not one filesystem transaction. The application database, identity and registration param.json are never rewritten.

Close Vortex normally and reboot/restart the PS5 shell with your normal procedure to discard in-memory artwork. Recheck home icon and earliest launch splash. If registration files are inaccessible or have another identity, the operation fails rather than guessing another target. Keep the diagnostic results for further investigation.

For rollback, explicitly choose **Restore backed-up Vortex artwork** in Settings. It checks current and backup identities, requires a complete backup for each target, restores only those artwork bytes and retains backups. Close Vortex and reboot the shell again. Restoring original artwork can intentionally restore the old icon. No user data is removed by either operation.
