# Updating and recovery

Vortex reads only `https://api.github.com/repos/tattedbeardo89/vortex/releases/latest`. Stable tags must be vMAJOR.MINOR.PATCH. Drafts, prereleases, malformed/older versions, missing SHA-256 digests, duplicate update assets and foreign download URLs are refused. There is no local feed override. The original catalog and provider APIs are separate from application self-updates and remain upstream services.

Only an image installation named Vortex.exfat is automatically updated; folder installs require a manual reinstall. ShadowMount lookup uses PPSA99189 and rejects an Overdrive path. Fallback discovery considers only Vortex.exfat and the PPSA99189 folder, and refuses ambiguous installations. The updater never searches for or overwrites Overdrive.exfat. Vortex has its own title data, queue path, pending marker and update work directory; Overdrive settings are not automatically migrated.

The native download verifies GitHub's update.zip SHA-256 and expected size. The archive must contain Vortex.exfat and vortex-update.json only (apart from framework extraction markers). The manifest must match Vortex name, repository, title/content IDs, requested version and image size. Unknown entries, foreign identity, malformed image size or invalid manifests fail before replacement. The manifest is integrity-bound by the trusted release ZIP hash, NOT independently signed or a runtime parse of an embedded exFAT title. This trusts the Vortex repository's maintainers and verified build pipeline; a compromised trusted release publisher is outside that guarantee.

Existing staging/cleanup and same-volume rename-over-image behavior are retained. Interrupted downloads, extraction failures and failed replacements do not intentionally delete the installed image; errors surface to the user and temporary files are cleaned on retry/startup. A pending marker detects an old still-running version after replacement. Console-specific mounted-image replacement, power-loss guarantees and launch behavior require hardware validation.

If an update fails: keep the app closed, preserve current state, download a known trusted Vortex.exfat from a Vortex release, and replace only the Vortex image. Never use an Overdrive image as a Vortex update. Keep backups outside homebrew so ShadowMount cannot register duplicate Vortex images. If a new build is broken, manually restore the prior trusted image or publish a higher-version corrective release; do not rewrite published tags. See RELEASING.md for version/asset rules.
